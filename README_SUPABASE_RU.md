# DevSpace — Supabase + PostgreSQL

Это переработка существующего `index.html`: сохранены основная разметка, оформление, каталог проектов, профили, список участников, лайки, публикация, загрузка/скачивание файлов и центр данных. Вместо прежнего Python API и локальной демонстрационной базы сайт использует Supabase Auth, PostgreSQL и Supabase Storage.

## Важно: что уже готово, а что требует настройки

- Код сайта и SQL-схема подготовлены.
- Аккаунты и проекты не хранятся в `localStorage` как основное хранилище.
- Для реального входа нужен собственный проект Supabase. Я не могу создать его от твоего имени или узнать твои ключи, поэтому `supabase-config.js` пока содержит явные заглушки. Пока ты не заменишь их и не выполнишь SQL, сайт специально не даст зарегистрироваться и не будет притворяться, что база подключена.
- Используй только Supabase Project URL и публичный `anon`/`publishable` key. **Никогда не вставляй `service_role` key или пароль базы в HTML/JS.**
- Вход через Google требует отдельно включить Google provider в Supabase Auth. Email/пароль работает через Supabase Auth.

## 1. Создать общую базу

1. Открой https://supabase.com/dashboard и создай проект Supabase.
2. В проекте открой **SQL Editor → New query**.
3. Открой файл `supabase_schema.sql`, скопируй весь SQL, вставь его в редактор и нажми **Run**.
4. В Supabase открой **Project Settings → API** (в некоторых версиях панели: **Connect**) и скопируй **Project URL** и публичный **anon/publishable key**.
5. Открой `supabase-config.js` и замени две строки-заглушки:
   - `https://YOUR_PROJECT_ID.supabase.co` → Project URL;
   - `YOUR_SUPABASE_ANON_OR_PUBLISHABLE_KEY` → публичный anon/publishable key.
6. Сохрани файл. Не отправляй приватные ключи в чат и не добавляй их в сайт.

## 2. Включить подтверждение email и Google

**Email:** Supabase → Authentication → URL Configuration. Укажи URL своего опубликованного сайта в Site URL и Redirect URLs. Для регистрации с подтверждением пользователь должен открыть ссылку из письма, затем войти по тому же email и паролю.

**Google (по желанию):** Supabase → Authentication → Providers → Google, включи provider и заполни OAuth Client ID/Secret из Google Cloud Console. В Google OAuth client добавь redirect URL, который Supabase показывает на странице настройки Google provider (обычно `https://<project-ref>.supabase.co/auth/v1/callback`). В URL Configuration добавь адрес сайта. Не вставляй Google Client Secret в файлы сайта.

## 3. Опубликовать

Это статический сайт — Python-сервер больше не нужен.

**Netlify (самый простой вариант):**
1. Распакуй `DevSpace_Supabase.zip`.
2. Перетащи папку `DevSpace_Supabase` или её содержимое в Netlify Drop: https://app.netlify.com/drop . Убедись, что `index.html`, `supabase-config.js` и `supabase_schema.sql` лежат в корне публикуемой папки.
3. Открой выданный HTTPS-адрес, добавь его в Supabase Authentication → URL Configuration.
4. Проверь регистрацию с реальным email и опубликуй тестовый проект.
5. Открой тот же адрес на телефоне и войди в тот же аккаунт — проекты должны совпасть.

Можно также разместить папку в GitHub Pages. После каждого изменения `supabase-config.js` и `index.html` должны публиковаться вместе.

## 4. Проверка

- Зарегистрируй аккаунт с никнеймом, email и паролем от 8 символов.
- Если включено подтверждение email, сначала подтверди адрес.
- Войди, опубликуй проект и прикрепи небольшой файл до 10 МБ.
- Открой «Участники»: ник должен быть в общем списке.
- Открой проект и нажми «Скачать файл».
- На другом устройстве открой тот же опубликованный адрес и войди в тот же аккаунт. Проекты/профиль загружаются из общей базы Supabase.

## Техническая схема

- **Supabase Auth:** регистрация, вход по email/паролю, сессии и Google OAuth.
- **PostgreSQL:** таблицы `profiles`, `projects`, `project_files`, `project_likes`.
- **Supabase Storage:** файлы и обложки проектов в bucket `project-files` (публичная загрузка файлов для скачивания; запись/удаление ограничены владельцем).
- **RLS:** политики ограничивают создание, изменение и удаление собственных профилей/проектов/файлов и лайков.
- **Лимиты:** до 10 файлов в проекте, каждый файл и обложка до 10 МБ.

## Ограничения миграции

Это новая схема хранения. Старые аккаунты, которые существовали только в `localStorage` или в прежней Python/PostgreSQL версии, автоматически не переносятся в Supabase. Старый JSON-экспорт остаётся резервной копией, но не является токеном входа. Не импортируй проекты вслепую в другой аккаунт: файлы и права владельца должны мигрировать отдельно.
