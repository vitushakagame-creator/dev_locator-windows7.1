# DevSpace — серверная версия на Python

Это не статическая демо-сборка. В опубликованной версии сайт отправляет запросы на Python/Flask API. Аккаунты, профили, проекты, лайки и метаданные файлов хранятся в PostgreSQL. Содержимое загруженных файлов хранится в DigitalOcean Spaces (S3-совместимое хранилище), поэтому файлы не пропадают при пересборке/перезапуске приложения.

## Важно перед публикацией

Одной загрузки ZIP в GitHub недостаточно. Нужно подключить постоянную базу PostgreSQL и хранилище Spaces в DigitalOcean. Если не настроить их, приложение при `REQUIRE_PERSISTENT_STORAGE=1` специально не запустится, вместо того чтобы молча использовать временный диск.

## DigitalOcean App Platform

1. Распакуй архив. Загрузи все файлы из этой папки в корень отдельного GitHub-репозитория (в том числе `index.html`, `server.py`, `requirements.txt` и `Procfile`). Не загружай ZIP как единственный файл.
2. В DigitalOcean создай приложение типа **Web Service** из этого репозитория. `Source Directory` оставь пустым, если файлы лежат в корне репозитория.
3. Команда сборки: `pip install -r requirements.txt`
4. Команда запуска: `gunicorn --workers 2 --bind 0.0.0.0:$PORT server:app` (также задана в `Procfile`).
5. Создай управляемую базу **PostgreSQL** в DigitalOcean и подключи её к приложению как переменную `DATABASE_URL`. Если интерфейс просит указать значение вручную, используй connection string базы и включи SSL (`sslmode=require`, если это требуется для выданной строки подключения).
6. Создай **Spaces bucket**. Создай ключ доступа Spaces (Access Key и Secret Key) с правами на этот bucket. Значения ключей нельзя публиковать в GitHub или присылать в чат.
7. В настройках приложения добавь переменные окружения:

| Переменная | Значение |
|---|---|
| `REQUIRE_PERSISTENT_STORAGE` | `1` |
| `DATABASE_URL` | строка подключения к PostgreSQL |
| `SESSION_SECRET` | длинная случайная строка, не менее 32 символов |
| `COOKIE_SECURE` | `1` |
| `SITE_URL` | публичный HTTPS-адрес этого приложения, без завершающего `/` |
| `SITE_ORIGIN` | тот же публичный HTTPS-адрес |
| `API_PUBLIC_URL` | тот же публичный HTTPS-адрес |
| `SPACES_ENDPOINT_URL` | например, `https://nyc3.digitaloceanspaces.com` — замени `nyc3` на регион своего bucket |
| `SPACES_REGION` | код региона bucket, например `nyc3` |
| `SPACES_BUCKET` | точное имя bucket |
| `SPACES_ACCESS_KEY` | Access Key Spaces |
| `SPACES_SECRET_KEY` | Secret Key Spaces |
| `GITHUB_CLIENT_ID` | Client ID GitHub OAuth App, если нужен вход через GitHub |
| `GITHUB_CLIENT_SECRET` | Client Secret GitHub OAuth App |
| `GITHUB_CALLBACK_URL` | `https://ТВОЙ-ДОМЕН/auth/github/callback` |

8. Создай GitHub OAuth App в настройках GitHub. В поле **Authorization callback URL** укажи в точности тот же адрес, что и в `GITHUB_CALLBACK_URL`. Если не нужен вход через GitHub, можно пока не задавать две переменные `GITHUB_CLIENT_*`; вход по имени и паролю продолжит работать.
9. Разверни приложение и открой `https://ТВОЙ-ДОМЕН/healthz`. При успешной настройке ответ содержит `"ok": true` и `"database": "connected"`. В production должно также отображаться `"fileStorage": "spaces"`.
10. Открой сам сайт с телефона и компьютера по одному и тому же HTTPS-адресу. Создай аккаунт, опубликуй тестовый проект и проверь, что он виден после входа на втором устройстве. Удалять тестовый проект можно из его страницы.

## Файлы проекта, подключённые к сайту

В разделе «Центр данных» сайта есть реальные ссылки `/tools/...` на `devspace_setup.py`, `devspace_import.py`, `devspace_data_helper.js` и эту инструкцию. Python-сервер отдаёт только эти четыре файла по allow-list; произвольные пути сервера недоступны.

- `devspace_setup.py` создаёт локальную папку проекта и копирует в неё сайт/файлы запуска и инструменты.
- `devspace_import.py` извлекает содержимое файлов из JSON-резервной копии аккаунта в локальную папку `Data/<ник>/`.
- `devspace_data_helper.js` проверяет и кратко описывает JSON-резервную копию.

Эти вспомогательные инструменты запускаются на компьютере, а не внутри браузера. Онлайн-сохранение сайта выполняет `server.py` через PostgreSQL и Spaces.

## Что хранится постоянно

- PostgreSQL: аккаунты, хеши паролей, профили, проекты, лайки и метаданные загруженных файлов.
- Spaces: содержимое прикреплённых файлов и изображений.
- Cookie входа хранится в браузере каждого устройства; на другом устройстве нужно войти в тот же аккаунт. Данные аккаунта и проектов общие.

Каждый прикрепляемый файл и изображение ограничен 10 МБ; к одному проекту можно прикрепить до 10 файлов и одно изображение. Весь один запрос ограничен 110 МБ.

## Локальный запуск для проверки

Нужен Python 3.10 или новее. В терминале из папки проекта:

```bash
python -m venv .venv
# Windows:
.venv\\Scripts\\activate
# macOS/Linux:
# source .venv/bin/activate
pip install -r requirements.txt
python server.py
```

Открой `http://127.0.0.1:8080`. Локально используется SQLite и папка `uploads` для проверки. **Для опубликованной версии оставь `REQUIRE_PERSISTENT_STORAGE=1` и настрой PostgreSQL + Spaces**, чтобы сервер не использовал временное локальное хранилище.

## Безопасность

- Не добавляй `.env` с секретами в репозиторий.
- Не присылай никому `GITHUB_CLIENT_SECRET`, `SPACES_SECRET_KEY`, `SESSION_SECRET` или строку подключения к базе.
- После публикации проверяй `/healthz` и логи сборки/запуска DigitalOcean.

## Примечание о старых данных

Сервер умеет однократно импортировать старый `data/db.json`, если такой файл присутствует рядом с сервером и новая база пуста. Это переносит метаданные, но бинарные файлы из старого временного хранилища необходимо отдельно перенести в Spaces, если они существуют. Данные, которые остались только в localStorage старого браузерного демо, автоматически на сервер не переносятся.
