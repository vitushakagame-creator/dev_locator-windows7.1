# DevSpace — исправленная версия с обычной регистрацией

## Что исправлено в этой сборке

- Исправлена конфигурация Render: проект запускается как **Python/Flask**, а не как Node.js.
- Удалён `package.json`, который пытался запускать отсутствующий `server.js`.
- В форме авторизации оставлены обычные имя пользователя и пароль; кнопка входа через GitHub убрана.
- Render использует постоянный диск `/var/data` для SQLite-базы и загруженных файлов.
- Пользователи и проекты выдаются из общей серверной базы через `/api/state`. Регистрация — `/api/register`, вход — `/api/login`.

## Как опубликовать на Render

1. Распакуй архив и загрузи **содержимое** папки `dev_locator-windows7.1-main` в корень репозитория GitHub. ZIP-файл как единственный файл не подходит.
2. На Render создай Blueprint из этого репозитория и подтверди настройки из `render.yaml`. Если сервис уже создан, проверь, что он использует Python и команду запуска `gunicorn --workers 2 --bind 0.0.0.0:$PORT server:app`.
3. Дождись завершения сборки и открой адрес приложения с `/healthz`. Ожидается JSON с `ok: true` и `database: connected`.
4. Открой главную страницу, создай аккаунт с именем и паролем от 8 символов. Создай второй аккаунт в другом браузере/приватном окне: оба аккаунта должны появиться в разделе участников.

В `render.yaml` настроен постоянный диск. Он нужен, чтобы локальная SQLite-база и загруженные файлы не пропадали при перезапуске. Убедись, что используемый план Render поддерживает persistent disk. Для масштабирования на несколько экземпляров лучше подключить PostgreSQL и S3-совместимое хранилище.

## Локальный запуск

Требуется Python 3.10+. В терминале из папки проекта:

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
# source .venv/bin/activate
pip install -r requirements.txt
python server.py
```

Затем открой `http://127.0.0.1:8080`. Локальные аккаунты будут храниться в `data/devspace.sqlite3`, а загруженные файлы — в `uploads/`. Локальная база не синхронизируется с опубликованным сайтом.

## Важно

- Обычная регистрация не требует GitHub OAuth.
- Для общих пользователей нужно открыть один и тот же опубликованный DevSpace URL, а не HTML-файл через `file://`.
- Я проверил структуру архива и синтаксис; фактическую публикацию на вашем аккаунте Render и работу после публикации нужно проверить на самом хостинге.
- Не добавляй секреты и пароли в репозиторий.
